Gemini・Groq・OpenRouterの3社はいずれも「クレジットカード登録なし」で無料APIキーを発行できます。万が一、短時間にたくさん問題を解いて無料枠の上限に達した場合でも、事後請求や自動課金に切り替わることはなく、単に「利用制限エラー（しばらく待ってから再試行）」になって止まるだけですのでご安心ください。

✨ Google Gemini API（無料枠が最も広く日本語も高精度）

【取得手順】

  1. Google AI Studio (API Keys) にGoogleアカウントでログインします。
  2. 右上の Create API key（APIキーを作成） を押し、表示された AIzaSy... から始まる文字列をコピーして本アプリに貼り付けます。
🔍 本当に無料か確認するポイント（英語表記の見方）:
  • APIキー一覧画面の右端にある Plan（プラン）列 を見て、Free of charge（または日本語で「無料」） と書かれていれば完全無料です。
  • Set up Billing（請求先の設定）という青いリンクが表示されている状態＝「まだ課金設定をしていない（＝無料枠で稼働中）」という意味です。
爆速・無料

⚡ Groq API（英語画面での取得＆無料プラン確認手順）

【取得手順（英語画面）】

  1. Groq Cloud Console を開き、Googleアカウント等でログイン（Sign in）します。
  2. 左メニューの API Keys をクリックし、画面中央または右上の Create API Key ボタンを押します。
  3. Display Name for API Key に適当な名前（例: quiz）を入力して Submit を押します。
  4. gsk_... から始まるキーが表示されるので、Copy を押して本アプリに貼り付けます（※一度閉じると再表示できないため、その場でコピーしてください）。
🔍 本当に無料か確認するポイント（英語表記の見方）:
  • 左メニュー下の Settings > Billing（請求） を開きます。
  • Current Plan: Free（現在のプラン：無料） と表示されていれば、完全無料で利用できています！
  • 画面に Upgrade to Developer Plan（有料の開発者プランへアップグレード）というボタンが出ていれば、現在は無料のFreeプランにいる証拠です。カード番号を入力しない限り料金は一切発生しません。
複数AI自動切替

🌐 OpenRouter API（無料確認＆「404エラー」を防ぐ必須設定）

【取得手順（英語画面）】

  1. OpenRouter Keys にアクセスし、右上の Sign in からGoogleアカウント等でログインします。
  2. Create Key ボタンを押し、Name に適当な名前（例: quiz）を入れます。
  3. Credit limit (optional)（利用上限額）は空欄または 0 のままで Create を押し、sk-or-v1-... のキーをコピーします。
🔍 本当に無料か確認するポイント ＆ ⚠️ 404エラー対策（重要）:
  • 無料の確認方法: 右上メニューの Credits（残高）が $0.00 で、カード登録（Add Credits）をしていなければ絶対に課金されません。本アプリ（QuaGenius）はOpenRouterの無料専用モデル（openrouter/free や末尾 :free）しか呼び出さない安全設計になっています。
  • ⚠️ OpenRouterで「404エラー」が出る場合の必須設定: OpenRouterで無料モデルを使うには、Settings > Privacy（プライバシー設定） を開き、Enable free endpoints that may train on inputs（および may publish prompts）のスイッチを ON（有効） にしてください。初期状態（OFF）のままだと、無料モデルへの通信がすべて 404 Not Found として拒否されます。
トラブル解決

💡 短時間に連続して問題を解くと「404」や制限エラーが出る理由

  • 原因1（短時間のリクエスト集中によるレート制限）: 無料API枠には「1分間に〇回まで（RPM制限）」というスピード制限があります。連続で問題を生成・スキップしたりAI講師に質問したりすると一時的に制限（HTTP 429）にかかります。
  • 原因2（旧バージョンのフォールバック上書きバグ → v2.1.2で修正済み！）: v2.1.1以前は、1番目のモデルが「429（スピード制限）」になった際、予備の旧モデル（提供終了で404を返すモデル）へ順番に切り替え、最後の「404エラー」でエラー表示を上書きしてしまう不具合がありました。
  • v2.1.2での改善: 廃止モデルを除去して現行モデルへ更新し、スピード制限（429）発生時は数秒のクールダウンを挟んで自動再試行するように改善しました。また、裏での「次の問題の先読み通信」も解答直後の通信とぶつからないよう間隔を空ける制御を導入しています。
